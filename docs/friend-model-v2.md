# 친구 모델 v2 — 접점 기반 상호 신청 + 친구 사적 실명 (확정)

> 작성: 2026-07-23 · 상위: docs/relationship-archive-design.md
> "점차 접점이 생기며 확장되는 사회" 세계관. 기존 일반 추천/수락 모델을 개편한다.

## 정체성 사다리 (핵심 원칙)
| 표면 | 표시 | 규칙 |
|---|---|---|
| 공개(마당·챌린지) | 익명(수달N·아무개N) | **친구가 돼도 영원히 익명**. 공개 화면 실명화 절대 금지 |
| 친구 알림 | 친구 실명 | 친구 성립 후 사적 알림에서만 |
| 친구 프로필 피드·아카이브 | 친구 실명 | 친구 성립 후 사적 화면에서만 |

## 1. 친구 자격 — 양방향 접점 임계값
- 조건: `A→B ≥ T` **AND** `B→A ≥ T` (각 방향 각각 충족, 엄격).
- `T = FRIEND_ELIGIBILITY_THRESHOLD` (config, 초기 100, 조정 가능).
- `FRIENDS_ENABLED` 글로벌 플래그로 순차 출시(초기 off).
- 자격 충족 쌍만 마이에서 "친구 신청 가능한 유저를 찾았어요!"로 노출.

## 2. 상호 신청 → 자동 친구 (수락 단계 없음)
- 자격 충족 상대에게만 신청 가능(임의 신청 차단).
- A 신청 → pending. B도 신청하면 **둘 다 신청 = 자동 친구 ON**. 별도 수락 없음.

## 3. 친구 된 후 — 익명 상호작용 알림 식별
- 친구가 익명으로 내 콘텐츠에 반응/댓글 → **알림에서만** "친구 OO님이 반응했어요"로 실명 식별.
- **공개 화면은 그대로 익명.** notification-worker가 actor↔recipient 친구 여부(graph) 확인 후 문구 실명화. 볼륨은 묶음발송.
- 동의: 친구 성립(양방향 100+ & 상호신청) 자체가 강한 동의 → **자동 ON**.

## 4. 친구 프로필 피드 실명 공개
- 친구끼리 프로필 피드 상호 열람 + 실명 표시(상호 팔로우 승격). 친구 성립 시 자동.

## 동의 정리
- 3·4는 **친구 성립 시 자동**(추가 동의 불필요).
- **아카이브 전체 콘텐츠(단계 E)만** 별도 상호 동의 유지(가장 민감).

## 데이터 모델 변경
- PAIRSTAT에 **방향별 카운트** 추가: `USER#A/PAIRSTAT#B { outCount(A→B), inCount(B→A), ...per-type, isFriend }`.
- projector: actor 파티션은 outCount++, target 파티션은 inCount++.
- 자격 조회: `USER#uid` 파티션에서 PAIRSTAT 스캔 → `outCount≥T && inCount≥T && !관계` 필터.
- 추천 점수/REC# gsi는 폐지(자격은 카운트 임계값 기반).

## 구현 순서
1. config(임계값·플래그) + projector 방향별 카운트
2. user-api 자격 후보 + 상호신청 자동친구 + 프론트 카피
3. 친구 알림 실명 식별(notification-worker graph 조회)
4. 친구 프로필 피드 실명(personal-feed 연동)
